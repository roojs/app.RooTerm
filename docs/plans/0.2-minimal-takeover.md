- **🔷** Persist to a **RooTerm JSON** config (not Ásbrú write-back).

- **⏳** One-shot **import from Ásbrú** into RooTerm JSON so existing hosts survive the switch.

## Passwords (how / where)

Ásbrú today: Blowfish/CBC hex blobs in YAML (`AsbruCipher` / `PACUtils.pm`) — decryptable once you know the scheme; **not** a real secret store.

- **🔷** Use **libsecret** (Secret Service — GNOME Keyring / KWallet): secrets never sit in the JSON file.
- **🔷** JSON holds non-secret fields only; secret lookup key = connection **uuid**.
- **🔷** First access may prompt the desktop **keyring unlock** dialog (login password / keyring password) — that is expected Secret Service behaviour, not something RooTerm invents.
- **🔷** On first import from Ásbrú: decrypt Ásbrú pass → store into libsecret → drop plaintext from memory after save.
- **🚫** Do not reinvent encrypted-in-JSON / Blowfish-in-config for new secrets.
- **🚫** Do not keep writing Ásbrú `asbru.yml` / `asbru.nfreeze`.
- **🚫** Do not store passwords in plaintext JSON.

## Config shape (JSON)

- **🔷** Path: **`~/.config/rooterm/connections.json`** (XDG).
- **💩** Schema sketch (confirm):
  - top-level `version`, `defaults` (font, window size), `connections[]`
  - each connection: `uuid`, `name`, `parent_uuid`, `is_group`, `host`, `port`, `user`, `auth` (`password` | `ssh_key` | `manual`), `deleted` (bool), `forwards[]`
  - each forward: `local_host`, `local_port`, `remote_host`, `remote_port`
  - **no** `pass` field in JSON when using libsecret
- **🔷** Soft-delete: set `deleted: true`, hide from tree/search; keep row (+ libsecret entry) so a later **Show deleted** / restore can bring it back.
- **🔷** Load order: if RooTerm JSON exists → use it; else **import Ásbrú once** and write JSON (then prefer JSON thereafter).
- **💩** Keep read-only Ásbrú fallback behind a flag only if import fails — confirm; default is migrate-and-own.

## UI

### Tree context menu

- **🔷** Right-click a **group** node → menu:
  - **Add connection** (parent = that group)
  - **Delete** — **enabled only if the group has no non-deleted children**; otherwise **insensitive / grayed out**
- **🔷** Right-click a **host** (terminal) node → menu:
  - **Edit connection** (same `ConnDialog`, loaded with that host)
  - **Delete** — **confirm** dialog, then soft-delete (`deleted` flag); hide from tree/search
- **🔷** Soft-delete keeps the record (and keyring secret) for a future **Show deleted** / restore UI.
- **🚫** Hard-delete / purge in this plan (unless a later “empty trash” plan).
- **🚫** **Add connection** on a host row.
- **🚫** **Edit connection** on a group row.
- **🚫** Full Ásbrú edit surface (Expect, clusters, RDP, etc.).

### Add / edit dialog

- **🔷** `ConnDialog` is an **Adw** dialog with a **stack / tabs**:
  - **Basic** — name, host, port, auth (radios + conditional user/password)
  - **Port forwarding** — list of forwards (see below)
- **🔷** Basic fields:
  - **Name** (tree label; also used for tabs / window title / search placeholder — **no separate Title field**)
  - **Hostname** + **Port** (default 22)
  - **Auth** row: three **radio** buttons — **Password** | **SSH key** | **Manual**
  - When **Password** selected: show **User** + **Password** (password entry with **Show** / reveal toggle so the value can be checked temporarily)
  - When **SSH key** or **Manual** selected: hide the password row; show **User** only
  - SSH key: no key-path field (agent / default keys)
  - Manual: no password stored; no auto-feed at prompts
- **🔷** Port forwarding tab:
  - **ColumnView** with columns: local address, local port, remote address, remote port
  - Columns are **sortable** (so you can sort by local port and spot a free port, e.g. 82)
  - Toolbar: **Add** and **Edit** on the left (**Edit** sensitive only when a row is selected); **Delete** on the right
  - **Double-click** a row → Edit
  - Add / Edit opens **`ForwardDialog`** (local address+port, remote address+port) — not in-place cell editing
  - **🔷** Guard against **duplicate** forwards (same local bind and/or same local port — refuse or warn; prefer refuse)
- **🔷** Save → write JSON (+ secret store) when Phase 9 glue is in; until then dialogs are not shipped half-wired.

### Tree icons

- **🔷** Groups: folder (existing symbolic is fine).
- **🔷** Hosts: **small** `utilities-terminal-symbolic` (or scaled app symbolic) — row-sized, not the large app icon.
- **ℹ️** Open-session markers stay as today (per-tab terminal buttons).

### SSH spawn

- **🔷** Password auth: VTE feed of secret from libsecret / memory (unchanged idea).
- **🔷** SSH key auth: spawn `ssh` without `-i` unless we add key path later.
- **🔷** Manual auth: spawn `ssh` with user@host; **do not** auto-feed password/passphrase.
- **🔷** Forwards: one `-L` per list row (`[local_host:]local_port:remote_host:remote_port`).

## Class / file list (named for implementers)

Short names only; approve before adding methods beyond these entry points.

- **`Config`** — load/save `connections.json`; one-shot Ásbrú import.
- **`SecretStore`** — libsecret get/set/clear by connection uuid (password).
- **`ConnDialog`** — add/edit connection (Adw dialog).
- **`ForwardDialog`** — local/remote host+port sub-dialog.
- **`HostTree`** — context menu + small host icon (extend existing).
- **`Connection`** — add `forwards`, `deleted`; keep single **`name`** for display everywhere.
- **🚫** Separate connection **title** field — use **`name`** only.
- **`SshTerminal`** — apply forwards on spawn; load password from `SecretStore` when needed.
- **ℹ️** Keep **`AsbruConfig` / `AsbruCipher`** for **import only** until migration is solid; then optional delete.

## Phases

Build **real UI**, then **glue** persistence. No no-op menus, no in-memory theater. Still loading Ásbrú read-only until Phase 9.

### Phase 7 — Tree icons (+ menu chrome only with Phase 8)

- **🔷** `✔️` Small terminal icon for hosts; folder for groups (`HostTree`, `pixel_size` 16).
- **🔷** `✔️` Context menus (**Add** / **Edit** / **Delete** rules as above) land **together with** Phase 8 dialogs — **🚫** no-op menu items, **🚫** toast, **🚫** fake in-memory add/delete.

### Phase 8 — ConnDialog + forwards (dialogs work; persist in Phase 9)

- **🔷** `✔️` `ConnDialog` tabbed stack: **Basic** + **Port forwarding**.
- **🔷** `✔️` Forwards **ColumnView** with **sortable** columns; Add + Edit (left), Delete (right); double-click → **`ForwardDialog`**.
- **🔷** `✔️` Duplicate-forward guard on add/edit.
- **🔷** `✔️` Wire tree menus → dialogs / confirm soft-delete UX.
- **🚫** Disk / keyring save in this phase — that is Phase 9 (closing the dialog may discard until glue exists, or Phase 8+9 ship close together).
- **🔷** `✔️` `SshTerminal.spawn` can apply `-L` once forwards exist on the model; password still Ásbrú decrypt until Phase 9.

### Phase 9 — Config + SecretStore + glue

- **🔷** `⏳` `Config` JSON read/write at `~/.config/rooterm/connections.json`.
- **🔷** `⏳` First-run / missing JSON: import from Ásbrú YAML → write JSON + libsecret.
- **🔷** `⏳` `SecretStore` (libsecret); meson `libsecret` dependency.
- **🔷** `⏳` **Glue**: menus, dialogs, soft-delete, forwards, and spawn all persist through `Config` / `SecretStore`.
- **🔷** `⏳` App prefers RooTerm JSON over live Ásbrú path after migrate.
- **🔷** `⏳` Soft-delete confirms, sets `deleted`, hides row; keep secret for later restore.
- **💩** `⏳` **Show deleted** / restore UI — later; schema supports it now.
- **💩** `⏳` Duplicate **connection** name/host warning on add — confirm if wanted beyond forwards.

### Phase 10 — Soft cutover

- **🔷** `⏳` Day-to-day path never writes Ásbrú.
- **💩** `⏳` Optional: menu “Re-import from Ásbrú” (destructive merge policy TBD).
