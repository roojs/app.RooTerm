# 0.5 — Dialog ↔ terminal Jobs (state machine)

**Status:** DONE

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; Vala via **`docs/coding-standards-router.md`**. Build: **`docs/build-rules.md`**.

**ℹ️** Follows **`docs/plans/done/0.3-DONE-session-states-history-guake.md`** Phase 13 side-effects. Live testing showed ConnDialog terminal jobs are erratic because there is **no owned schedule** — only nested callbacks.

---

## Purpose

- **🔷** The fundamental problem is **unstructured scheduling**: button handlers close the dialog, open a VTE, and attach competing `present` / `Timeout` / `close_tab` callbacks.
- **🔷** Land a **`Jobs/`** folder: base **`Job`** holds shared components + **async helpers**; each action **extends** it as a **yield flow** of outcomes.
- **🔷** Step *bodies* stay on methods we already have (`SshStream` ``on_*`` / flags, `SessionController.create`, `KeyDialog`, …). Base helpers wrap them as awaitables; subclasses only sequence `yield`s.
- **🚫** More ad-hoc `present()` / `Timeout.add_seconds` / dual `close_tab.connect` in `ConnDialog` construct.
- **🚫** One mega-`ConnWorkflow` with a job enum and a giant switch — prefer **subclass per action**.

---

## What’s wrong today

```
ConnDialog button
  → close()
  → sessions.open(stream with flags)
  → key_installed / containers_found: stage; Timeout 2s → close_tab; present(dialog)
  → close_tab: present(dialog) again
```

- **🔷** No single owner of “which step am I on?”
- **🔷** Success and tab-close both drive UI → races / dialog pops back oddly
- **🔷** Nested `KeyDialog` then terminal then `AlertDialog` then ConnDialog — order undefined
- **🔷** Same pattern copied for setup key / upgrade / retire / fetch hosts

## Design target — `Jobs/` + base + subclasses

```
src/Jobs/
  Job.vala              ← State, expect, on_content; SshStream conclusion wiring
  SshLogin.vala         ← login(); SSH password / shell on_content
  SudoLogin.vala        ← login + sudo(); sudo / root on_content
  SetupKey.vala         ← password → KEY_INSTALLED (ssh-copy-id)
  ReplaceKey.vala       ← SetupKey + old_identity
  RetireKey.vala        ← login → strip authorized_keys → KEY_RETIRED
  FetchHosts.vala       ← login + sudo → lxc-ls → CONTAINERS_FOUND
```

```
Job
 └── SshLogin
      ├── SetupKey
      │    └── ReplaceKey
      ├── RetireKey
      └── SudoLogin
           └── FetchHosts
```

- **🔷** Simpler login is the **base class**; sudo (and later jobs) **extend** that flow.
- **🔷** Shared prefixes: `SshLogin.login()`, `SudoLogin.sudo()`; subclasses `yield` those then add steps.
- **🔷** Generic **`this.terminal.terminal.feed_child`** for passwords / ``sudo -i`` / commands (no `send` wrapper).
- **🔷** **`JobError`** (TIMEOUT / CANCEL / FAIL) — stop paths are **exceptions**, not Outcome/Event switches.

### Stop paths = exceptions

Bare “wait until state X” is not enough — **X may never happen**. **`expect` throws {@link JobError}**:

| JobError | Meaning |
| -------- | ------- |
| `TIMEOUT` | Deadline elapsed; wanted state never came |
| `CANCEL` | User closed helper tab / cancelled dialog |
| `FAIL` | Hard failure (sudo rejected, connection died, …) |

MATCH = `expect` returns ``true``. Timeout = ``false`` (caller checks `current_state`). Cancel/fail still **throw**. Subclass flows: ``if (!yield expect(…)) { … }``.

**State** = waits (prompts we park on) **or** conclusions (success or error). Error conclusions make **`expect` throw {@link JobError}**. Unrecognized buffer text stays **`UNKNOWN`** (do not overwrite a real `current_state`).

| Kind | Examples |
| ---- | -------- |
| Wait | `WAIT_HOST_CONFIRM`, `WAIT_VERIFICATION_CODE`, `WAIT_SSH_PASSWORD`, `WAIT_SHELL_PROMPT`, `WAIT_SUDO_PASSWORD`, `WAIT_ROOT_PROMPT`, `WAIT_KEY_DIALOG`, … |
| Success conclusion | `KEY_INSTALLED`, `KEY_RETIRED`, `CONTAINERS_FOUND`, `DONE` |
| Error conclusion | `FAILED`, `CANCELLED`, `TIMEOUT` → throw `JobError.FAIL` / `CANCEL` / `TIMEOUT` |

### Flow shape (expect → feed_child → expect)

```
while (!yield expect(WAIT_SSH_PASSWORD)) {
  // false — caller checks current_state (host confirm → retry; shell → return; else throw)
}
this.terminal.terminal.feed_child((pass + "\n").data)
if (!yield expect(WAIT_SHELL_PROMPT)) { throw TIMEOUT }
// SudoLogin:
this.terminal.terminal.feed_child("sudo -i\n".data)
if (!yield expect(WAIT_SUDO_PASSWORD)) { throw TIMEOUT }
this.terminal.terminal.feed_child((pass + "\n").data)
if (!yield expect(WAIT_ROOT_PROMPT)) { throw TIMEOUT }
```

- **🔷** **`expect(want, timeout) → bool`** — one state only. ``true`` = got it; ``false`` = timeout **or** another classified state (``current_state`` unchanged by timeout). Cancel/fail still **throw**.
- **🔷** Caller: ``if (!yield expect(…)) { switch (current_state) … }``.
- **🚫** Multi-want arrays / host-key / feed policy inside `expect`.
- **🔷** Focus: **host-key confirm** and **2FA verification code** → `present` / `grab_focus` in {@link SshLogin.on_content} (user types). **Shell prompt** → caller (`OpenSession`) after login success only.
- **🔷** Feed via **`this.terminal.terminal.feed_child`** (RooTerm `Terminal` → VTE).
- **🚫** `send()` wrapper / `cancel()` wrapper.
- **🚫** Stashing `SourceFunc` **fields** on the job to resume waits (local resume inside `expect` is fine).
- **🔷** Mock `SshLogin` / `SudoLogin` under `src/Jobs/` (wired via ConnDialog / `refresh_containers`).
- **🔷** `✔️` `WAIT_HOST_CONFIRM` — classified in `on_content`; handled in `login` / `SetupKey.run` when `expect` returns false.

### Lifetime — Job creates tab; wrapping ctor spawns

```
var job = new SetupKey(this.window, this.target);
// Job: sessions.create + live stream
// SetupKey ctor: install_key + signals
yield job.run();   // spawn, then expect flow
```

- **🔷** `SessionController.create` = tab + term, **no** spawn / **no** `grab_focus` (interactive callers spawn then focus).
- **🚫** `SessionController.open` wrapper (callers use create + spawn + grab_focus).
- **🔷** Job ctor `(MainWindow, Connection)` → `sessions.create` → adopt live `stream` → wire VTE / `close_tab`.
- **🔷** Wrapping subclass ctors set stream flags / connect signals only.
- **🔷** Subclass `run()` starts with `terminal.spawn()`, then the yield flow.
- **🚫** Spawn in ctors / `get_type()` spawn guards / spawn inside `expect`.
- **🔷** Subclasses keep **`run()`** (not renamed to `execute`).
- **🔷** `SshTerminal` **adopts** a passed `SshStream` (`attach`) — same object for flags and signals.
- **🚫** `install_key` / `install_identity` on the Job base.
- **🚫** Inventing Job `start` / `open_terminal` / renaming `run` → `execute` without asking.

### How `expect` works (`want` ↔ `current_state`)

Two roles, two properties — **do not** overload one name for both:

| Property | Who sets it | Meaning |
| -------- | ----------- | ------- |
| **`want`** | `expect(want, …)` | What this wait is hoping to see |
| **`current_state`** | content classifier (`on_content`) | What the VTE looks like right now |

```
contents_changed (construct)
  → on_content(cursor_line)   // subclass classifies → current_state
tab close → CANCELLED
expect timeout → TIMEOUT
SetupKey construct: key_installed → KEY_INSTALLED
SudoLogin construct: sudo_password_failed → FAILED

expect(WAIT_SSH_PASSWORD):
  park on notify["current_state"] until want OR error conclusion
```

- **🔷** **`on_content` is `virtual`** — each job overrides for its prompts, then ``base.on_content`` for the parent.
- **🔷** Job base = terminal wire + `expect` / `on_content` / `want` / `current_state` only.
- **🔷** Job-specific conclusions stay on that job (`SetupKey` → `key_installed`, `FetchHosts` → `container_names`, …).
- **🔷** Setting `want` must **not** be the same property as `current_state`, or the wait wakes itself.
- **🚫** Stuffing SetupKey / FetchHosts / stream handlers into `Job`.
- **🚫** `expect` polling in a busy loop; park on notify + timeout source.

### Base `Job`

- **🔷** Holds: `Terminal` (construct), `window`, `connection`, `want`, `current_state`.
- **🔷** Named API: `expect` / `on_content` / `run`.
- **🚫** `present(ConnDialog)` while waiting on a job step.
- **🚫** Key/container/stream-specific fields on the base.

### Concrete jobs — inheritance flows

| Class | Extends | Flow |
| ----- | ------- | ---- |
| `SshLogin` | `Job` | password → feed_child → shell → DONE |
| `SudoLogin` | `SshLogin` | `login` → `sudo` → DONE |
| `SetupKey` | `SshLogin` | password → `KEY_INSTALLED` → DONE |
| `ReplaceKey` | `SetupKey` | same as SetupKey; holds `old_identity` for ConnDialog |
| `RetireKey` | `SshLogin` | `login` → strip ``authorized_keys`` line → `KEY_RETIRED` → DONE |
| `FetchHosts` | `SudoLogin` | `login` → `sudo` → `lxc-ls` → parse → `container_names` / `CONTAINERS_FOUND` → DONE |
| `OpenSession` | `SudoLogin` | mock open-ended: login → optional sudo → optional `lxc-console` → DONE; **`keep_open`** (tab stays) |

- **🔷** Pick the login base that matches the connection (`SshLogin` vs `SudoLogin`), then extend for the job.
- **🔷** `✔️` One-shot jobs wired (ConnDialog / `refresh_containers`).
- **🔷** `✔️` Mock (not wired): `OpenSession` — replaces interactive `SshStream` auto login/sudo/lxc later.
- **🔷** `Job.keep_open` — interactive session stays; **caller** closes one-shot helper tabs (`close_tab`) after `run`.
- **🔷** `OpenSession.login` override — wait for password/passphrase **or** shell; feed passphrase if set, else password.
- **🔷** `✔️` Wire `OpenSession` from MainWindow host open / empty page + `SessionController.open_new`.
- **🔷** `✔️` Strip `SshStream` auto password / sudo / ``lxc-console`` feeds (Jobs own those).
- **🔷** `✔️` Sudo fail detection lives in `SudoLogin` (not `SshStream`); passphrase feed stays in `OpenSession.login`.
- **💩** Namespace `RooTerm.Jobs` vs flat `RooTerm` with files under `src/Jobs/`.
- **💩** Dead-tab **reconnect** still only `spawn()` — needs OpenSession (or similar) on the existing tab.
- **💩** `SshStream.on_key` / `install_key` still stream-side for SetupKey.
