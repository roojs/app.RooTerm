# 0.14 — Tree expand save / restore

**Status:** ⏳ not started

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; Vala via **`docs/coding-standards-router.md`**. Build: **`docs/build-rules.md`**.

**ℹ️** Same save/restore flow as local tabs (**`docs/plans/0.13-DONE-auto-restore-local-tabs.md`**): field on `Connection`, dump in `connections.json`, save on change, apply on launch.
**ℹ️** Wishlist pointer in **`docs/plans/0.9-tidy-up.md`**.

Edits are **Remove** / **Replace with** / **Add** from the tree; verify surrounding context before applying.

---

## Purpose

- **🔷** Persist which tree rows are expanded in `connections.json` (groups / hosts / etc.).
- **🔷** Save when the user expands or collapses a row.
- **🔷** On launch, restore expand state.
- **🔷** Localhost is **always expanded** on load — do not persist its expand state.
- **ℹ️** Today `Gtk.TreeListModel` is constructed with ``autoexpand = true`` — everything starts open; nothing is saved.

---

## Current behaviour

- **ℹ️** `Host.Tree` — `new Gtk.TreeListModel(..., false, true, …)` (autoexpand on).
- **ℹ️** Expand state lives only on live `Gtk.TreeListRow` — gone on quit.
- **ℹ️** Localhost stays synthetic (not in JSON) — unchanged by this plan.

---

## Behaviour

- **🔷** `Connection.expanded` (bool) — serialized; default ``true`` (matches today’s autoexpand).
- **🔷** TreeListModel ``autoexpand = false``.
- **🔷** On `factory.bind`: set the row from connection (Localhost always open); then wire ``expanded`` notify → save (skip Localhost).
- **ℹ️** Expanding a parent creates child rows → their `bind` applies their own saved state (no separate walk of the model).
- **🚫** Persist / restore Localhost expand; put Localhost in `by_uuid` for this feature.
- **🚫** Post-construct loop over `tree_model` to force expand.

##### Part 4 — `factory.bind`: apply expand, then persist toggles

#### Add — at start of `factory.bind` handler, after `var conn = (Connection) ((Gtk.TreeListRow) list_item.item).item;`

Apply saved (or Localhost-forced) expand before connecting notify, so restore does not `save()`.

```vala
				var list_row = (Gtk.TreeListRow) list_item.item;
				var want = conn.kind == ConnectionKind.LOCAL || conn.expanded;
				if (list_row.expanded != want) {
					list_row.expanded = want;
				}
				var old_exp_sid = list_row.get_data<ulong>("expanded-sid");
				if (old_exp_sid != 0) {
					list_row.disconnect(old_exp_sid);
				}
				list_row.set_data<ulong>("expanded-sid", list_row.notify["expanded"].connect(() => {
					if (conn.kind == ConnectionKind.LOCAL) {
						return;
					}
					if (conn.expanded == list_row.expanded) {
						return;
					}
					conn.expanded = list_row.expanded;
					this.config.save();
				}));
```

##### Part 5 — `factory.unbind`: drop expand handler

#### Add — in `factory.unbind`, after resolving `list_item` (and before or after other cleanup)

```vala
				var list_row = list_item.item as Gtk.TreeListRow;
				if (list_row != null) {
					var exp_sid = list_row.get_data<ulong>("expanded-sid");
					if (exp_sid != 0) {
						list_row.disconnect(exp_sid);
						list_row.set_data<ulong>("expanded-sid", 0);
					}
				}
```
