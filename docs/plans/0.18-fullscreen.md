## Purpose

- **🔷** Full-screen terminal mode (not just a prefs accel with no behaviour).
- **🔷** Control: icon to the **right of the ``+``** on the tab strip.
- **🔷** In full screen the same control shows a **half-screen / restore** icon (exit).
- **🔷** In full screen: **tabs + that chrome at the top** (not bottom).
- **🔷** Animate the transition (quick — see **Animation**).
- **🔷** Shortcut + VTE context-menu entry ship with this feature (``key-fullscreen``).
- **🔷** Persist full-screen in **config** — once on, stay on across hide/show / sessions until the user exits.

## Layout

### Docked (today — keep)

```
┌ host tree │ VTE tabs…                    ┐
│ + search  │                              │
│           │──────────────────────────────│
│           │ [tab][tab] …  blank  [+]     │  ← TabBar bottom
└───────────┴──────────────────────────────┘
```

### Full screen (target)

```
┌ host tree │ [tab][tab] …  blank  [+] [restore] │  ← strip TOP
│ + search  │────────────────────────────────────│
│           │ VTE (fills remaining work area)    │
│           │                                    │
└───────────┴────────────────────────────────────┘
```

- **🔷** Full screen: tab strip (tabs + ``+`` + full-screen control) sits **above** the VTE.
- **🔷** Exit: strip returns to **bottom**; icon back to expand / full-screen.
- **🔷** Steady state: **one** ``Host.TabBar`` (reparented or reordered).
- **🔷** **Keep** host tree + search in full screen (do **not** hide).
- **💩** Bottom ``drop-shadow`` hidden while full screen. Confirm.
- **ℹ️** ``Host.Page`` today ``append(tab_view); append(tab_bar)``. Full screen steady state = bar first, then VTE.

### Icon

- **🔷** Reserve space **right of ``+``** always (docked and full screen) so the strip does not jump.
- **🔷** Icons (symbolic): expand → full screen; restore → half-screen / leave full screen.
- **💩** Concrete names (pick when implementing): e.g. ``view-fullscreen-symbolic`` / ``view-restore-symbolic`` (or ``window-restore``). Confirm in review.
- **🔷** Button activates ``win.fullscreen`` (toggle).

## Window / Shell geometry

- **🔷** Full screen fills the **monitor work area** — the space **below** the GNOME Shell top bar (apps / clock / etc.), **not** OS compositor fullscreen over that panel.
- **🔷** Not only flipping the tab strip: window must grow to that work-area size.
- **ℹ️** Docked main is Shell-positioned (``DockMode`` / ``Redock``). Growing height via prefs percent alone may still leave the under-panel dock contract.
- **🔷** Approach: tell Shell to size ``main`` to the monitor **work area**; stay undecorated; keep Register/Show/Hide. Tab chrome on top. (“Huge Guake”, not F11-over-panel.)
- **🚫** GTK / compositor ``fullscreen()`` that covers the Shell top bar.
- **🚫** Second Meta window for full screen — keep one ``main`` role.
- **🔷** **F12** while full screen: **exit full screen** with the **same kind of collapse animation** as a normal dock hide, then hide (standard toggle path — not “stay full screen across hide”).
- **🔷** After hide/show while still “full screen” in config: restore work-area full screen again (locked until user exits via control / F11).

## Animation

**🔷** (2026-08-11) Intent: tab bar goes **translucent**, **fades out**, then **slides out** — all **pretty quick**. Exit reverses (slide/fade bar back to docked bottom as window collapses to normal dock height).

**ℹ️** Earlier plan text about a **“black spacer morph”** (fade bar to solid black → empty black boxes grow/shrink at top and bottom) was **LLM elaboration**. Alan did **not** recognize that wording — **not** the chosen design unless he re-adopts it.

### Steady state

- **🔷** **No** second interactive ``TabBar``.
- **🔷** One real ``TabBar``: bottom when docked, top when full screen.

### Enter / leave (💩 detail until fenced)

- **🔷** Bar: translucent → fade out → slide away (quick).
- **🔷** Window: grow/shrink to work area (Shell) in parallel with the chrome move.
- **💩** Exact GTK mechanism (opacity + ``translate`` / height vs reparent timing) — propose fences when implementing; keep it short (e.g. ~200–350 ms).

### Rejected / not chosen

- **🚫** Dual live tab bars during animation.
- **🚫** “Black spacer morph” as previously written (unless Alan brings it back).
- **🚫** Tab scatter / CRT iris / kangaroo hop as default.
