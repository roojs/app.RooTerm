# 0.23 — Script sender and sqlite tree

**Status:** ⏳ proposed

**Pointer:** `docs/guide-to-writing-plans.md` — **Checklist for plans**; Vala via **`docs/coding-standards-router.md`**. Build: **`docs/build-rules.md`**.

**ℹ️** Next number after **0.22** search cursor (`docs/plans/0.22-search-result-cursor.md`).

**ℹ️** Script and task shape follows Argus `shared/SQT/Script.vala` and `shared/SQT/Task.vala`. The tick grid follows `argusrm/controller/dialog/Upgrade.vala`. Storage is `SQ.Database` / `SQ.Query` from libocsqlite (`OLLMchat/libocsqlite`).

Code fences for these new files land after this shape is agreed. This document is the behaviour and the schema.

---

## Purpose

- **🔷** A **Script sender** window lists scripts and creates them in a form dialog.
- **🔷** **Execute** picks servers with the Argus tick grid, then creates a **task**.
- **🔷** The task runs in a **batch** window.
- **🔷** That window has two views: **Planning** and **Running**.
- **🔷** Running starts one terminal per ticked machine and uses the RooTerm login flow.
- **🔷** Those terminals live in the batch window. You can switch which one you are looking at.
- **🔷** Running shows progress: each command has run and completed.
- **🔷** When the run is finished, one close dismisses that batch and every terminal in it.
- **🔷** A batch against an LXC container uses `lxc-attach`, not `lxc-console`.
- **🔷** The host **tree** moves into a sqlite database through **ocsqlite**.
- **🔷** Script, task, and the related tables keep the **full Argus columns**, so this database can grow into that model later.
- **🔷** Row classes live in `src/SQT/`. Later UI follows Argus: `src/tab/`, `src/dialog/`, `src/store/`.
- **⏳** Phase 1 is the database and the tree. Phases 2–4 are still the windows.

---

## Current behaviour

- **ℹ️** The tree is `~/.config/rooterm/connections.json`. `Host.TreeNodes.load` / `save` read and write the whole nest. `ConfigMigrate` still folds an old combined file into that JSON.
- **ℹ️** `Host.Connection` is the live row and the JSON document. Passwords and passphrases are libsecret, keyed by `uuid` (LXC uses the parent uuid). They are not in the file.
- **ℹ️** `kind` is a JSON integer. Enum order is permanent (`HOST`, `GROUP`, `LOCAL`, `LOCAL_PATH`, `LXC`).
- **ℹ️** Sibling order is array order. Parent link is `parent_uuid`. Forwards are a nested array on the connection.
- **ℹ️** `expanded` is in the JSON. Saving it on toggle is parked (`docs/plans/done/0.14-DONE-tree-expand-save-restore.md`).
- **ℹ️** An interactive LXC session is `Jobs.OpenSession`: spawn, `login`, optional `sudo -i`, then `lxc-console -n NAME`.
- **ℹ️** `Jobs.Job` builds its terminal through `Session.Controller.create`, so the tab lands on the main window.
- **ℹ️** Chrome (`config.json`: theme, font, workspace last tab) is separate from the tree.
- **ℹ️** Shell owns `main` and `preferences` only. The connection editor is an ordinary GTK window.

---

## Proposed behaviour

- **🔷** One database file: `~/.config/rooterm/rooterm.db`.
- **🔷** Open it with `SQ.Database`. Rows go through `SQ.Query`.
- **🔷** `config.json` stays the chrome file. Libsecret stays the password store. `uuid` stays the secret key.
- **🔷** First launch that finds `connections.json` and an empty database loads that JSON, inserts the rows, and renames the file to `connections.json.migrated`.
- **🔷** After that, the tree loads and saves through sqlite. A later `connections.json` is not read again.
- **🔷** The database file stays open. There is no whole-tree save. An edit inserts, updates, or deletes that one row.
- **🔷** Script sender and each batch are ordinary GTK windows, like the connection editor. They are not new Shell roles.
- **🔷** Script sender stays open while a batch runs. Closing a batch does not close the sender.
- **🔷** A batch terminal is not a main-window tab. `Session.Controller.create` is not used for it.
- **🔷** Interactive **Open** on an LXC row still uses `lxc-console`. Only a batch uses `lxc-attach`.

## Phase 1 — Tree in sqlite

- **🔷** `⏳` Link `sqlite3` and `ocsqlite`: `dependency('sqlite3')`, `cc.find_library('ocsqlite')`, `--pkg sqlite3`, `--pkg ocsqlite`.
- **🔷** `⏳` `docs/build-rules.md` gains `libsqlite3-dev`.
- **🔷** `⏳` `src/SQT/` holds the row classes. `SQT.init_db` creates every table below, including the Argus ones, on open.
- **🔷** `⏳` `RooTerm.SQT.Connection` is the stored row. `Host.Connection` extends it and keeps the live fields (`parent`, `sessions`, `children`, `forwards`, `pass`, `passphrase`).
- **🔷** `⏳` `RooTerm.SQT.Forward` is one `-L`. `Host.Forward` extends it.
- **ℹ️** ocsqlite `setObjectProperty` calls `GLib.error` when an enum column is `0`. `ConnectionKind.HOST` is `0`, so the column is `kind_code` (`int`), not an enum. Save copies `kind` into it. Load copies it back. The numeric values stay the JSON values.
- **🔷** `⏳` `connection` columns:

```
id                 INTEGER   primary key
uuid               TEXT
parent_uuid        TEXT      empty on a root
position           INTEGER   sibling order, was JSON array order
name               TEXT
cwd                TEXT
expanded           INTEGER
kind_code          INTEGER   ConnectionKind, same numbers as the JSON kind
method             TEXT
host               TEXT
port               INTEGER
user               TEXT
auth               TEXT
public_key         TEXT
retire_key         TEXT
options            TEXT
deleted            INTEGER
sudo_after_login   INTEGER
lxc_host           INTEGER
lxc_name           TEXT
added_dt           INTEGER
updated_dt         INTEGER
deleted_dt         INTEGER
```

- **🔷** `⏳` `forward` columns:

```
id              INTEGER   primary key
connection_id   INTEGER   connection.id
position        INTEGER
local_host      TEXT
local_port      INTEGER
remote_host     TEXT
remote_port     INTEGER
added_dt        INTEGER
updated_dt      INTEGER
deleted_dt      INTEGER
```

- **🔷** `⏳` Passwords are not columns.
- **🔷** `⏳` `expanded` is stored. Toggling it still does not save, same as now.
- **🔷** `⏳` Open `rooterm.db` as the sqlite file. `SQ.Query` inserts and updates that file. `backupDB()` is not how a save is stored.
- **🔷** `⏳` No `TreeNodes.save`. `migrate()` inserts the imported tree once. A later edit inserts, updates, or deletes that one row.
- **🔷** `⏳` First launch with `connections.json` and an empty `connection` table loads that JSON, `migrate()` inserts the rows, and renames the file to `connections.json.migrated`.
- **🔷** `⏳` `ConfigMigrate` still builds the nest from an old combined file, then `migrate()` inserts it.
- **🔷** `⏳` Same open also creates the Argus tables, empty, full columns. No UI yet.

```
script
id, script_repository_id, path, filetype, platform, app, action, body, allow_all
added_dt, updated_dt, deleted_dt

script_perm
id, script_id, agent_id
added_dt, updated_dt, deleted_dt

script_repository
id, name, url, username, password, key
added_dt, updated_dt, deleted_dt

task
id, name, is_script, command, script_id, dist_version_id, run_as,
is_template, is_draft, scheduled, completed, created_by, approved_by,
controller_sig, server_sig, expires_at

task_target
id, task_id, agent_id, scheduled, started, ended, success,
is_cancelled, is_watched, timeout, identifier, log_dir
added_dt, updated_dt, deleted_dt
```

- **ℹ️** Those columns match `argusrm/shared/SQT/` `Script`, `ScriptPerm`, `ScriptRepository`, `Task`, and `TaskTarget`. Display-only Argus properties are not columns and are not copied.

## Phase 2 — Script sender

- **🔷** `⏳` The `script` table from Phase 1. The form edits `path` (the list label) and `body`. Other Argus columns stay on the row at their defaults.
- **🔷** `⏳` Window title **Script sender**. A `src/tab/` page, opened from the terminal right-click menu on the main window.
- **🔷** `⏳` The list is a `src/store/` over `SQT.Script`. A row opens a `src/dialog/` form. **New** opens it empty.
- **🔷** `⏳` Save inserts or updates the row and refreshes the list.
- **💩** `⏳` Delete on the form, with a confirm. A script that a task still points at stays in the database. The task keeps `command` as the body copy.

---

## Phase 3 — Planning

- **🔷** `⏳` **Execute** on a script opens a batch window on **Planning** and inserts a `task`. `script_id` is the library row. `command` is a copy of `script.body`. `is_draft` stays 1 while planning.
- **🔷** `⏳` A tick inserts a `task_target` (`agent_id` holds `connection.id` until a real agent id exists). Clearing it removes that target. This is only while `is_draft` is 1.
- **🔷** `⏳` **Run** needs at least one target. It sets `is_draft` to 0 and switches the window to **Running**.
- **💩** `⏳` How far through the body a machine got is stored in `task_target.identifier`, so the Argus table stays unchanged.
- **🔷** `⏳` Planning is the tick grid from Argus Upgrade.
  - A check column bound both ways to `picked`.
  - Search.
  - **Select all** / **Select none** for the rows the filter is showing.
- **🔷** `⏳` The rows are hosts and LXC containers. Groups and local paths are not in the list.
- **💩** `⏳` Localhost is not in the list. This is servers.
- **💩** `⏳` You can open more than one batch. Each batch is its own window.

---

## Phase 4 — Running

- **🔷** `⏳` One terminal per target, all started together, all inside this batch window.
- **🔷** `⏳` A machine list shows each target: logging in, running, done, or failed. Picking a row shows that terminal.
- **🔷** `⏳` The other terminals keep running while you look at one.
- **🔷** `⏳` Next to the terminal, `task.command` split into lines. Lines before `identifier` are complete. The current line is the one in flight. Blank lines are skipped.
- **🔷** `⏳` Login is the `OpenSession` flow: spawn `ssh` to the host (the parent host for an LXC row), password / passphrase / host-key confirm / verification, then `sudo -i` when `sudo_after_login` is set.
- **🔷** `⏳` Present and focus the **batch** window for that login. Do not raise the main drop-down.
- **🔷** `⏳` After the shell (and sudo, when set), an LXC target is `lxc-attach -n NAME`, then wait for the shell prompt. Not `lxc-console`.
- **🔷** `⏳` Then each remaining line is fed, and the job waits for the shell prompt before the next line. A prompt bumps `identifier`.
- **🔷** `⏳` The last line sets `ended` and `success` 0. A timeout or a failed login sets `ended` and a non-zero `success`, and leaves the terminal on screen.
- **💩** `⏳` One machine failing does not stop the others.
- **🔷** `⏳` When every target has `ended` set, `task.completed` is set. The window stays up.
- **🔷** `⏳` **Close** destroys that batch window and every terminal it owns, in one action. Main-window sessions stay.

---

## Suggested order

1. Phase 1 — database, migrate the tree, then insert or update the one row that changed.
2. Phase 2 — script list and form.
3. Phase 3 — task, targets, planning tick grid.
4. Phase 4 — terminals, login, `lxc-attach`, command progress, close.

## LLM notes

- **ℹ️** `SQ.Interface` in Argus is not part of libocsqlite. `SQ.Query` only needs a GObject. Do not copy that interface in for this.
- **ℹ️** Do not add Shell roles for these windows.
- **ℹ️** Do not put batch terminals on `Host.Stack`.
- **ℹ️** Do not change `OpenSession` off `lxc-console`.
- **ℹ️** Do not store `pass` or `passphrase` in sqlite.
- **ℹ️** Code fences for the new files come after this plan is agreed. Do not invent a second schema in the implementation.
