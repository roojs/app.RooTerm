#### Auto-restore open tabs (local first)

- **🔷** **Kinda critical / annoying** — does not work yet; bump urgency (daily reopen of local cwd tabs).
- **🔷** Start with **local cwd paths** under Localhost; SSH reconnect is a later step (“startup login”).
- **ℹ️** Today `LOCAL_PATH` rows are ephemeral:
	- created in {@link Host.Page}.`add`, removed on tab close
	- **not** registered in `config.by_uuid` → `Config.save` never writes them
- **🔷** Persist open local sessions as `LOCAL_PATH` connections in `connections.json` (same dump as hosts/groups).
- **🔷** Write / update that dump when the set of open locals changes:
	- **open** — new local tab → append `LOCAL_PATH` under Localhost + `by_uuid` + `save`
	- **close** — tab closed → remove that row + `save`
	- **label changes** — cwd / peer user changed → update the row (path + display name) + `save`
- **🔷** What to store per open local tab (enough to reopen in the right folder):
	- absolute **cwd** (spawn directory) — not only the display label (`~/…` / `root:…`)
	- stable `uuid` + `parent_uuid` = Localhost
- **🔷** Restore at startup:
	- after tree load, for each non-deleted `LOCAL_PATH` under Localhost → open a **normal-user** local shell in that folder
	- **skip / drop** rows whose path no longer exists (no reopen, prune from config)
	- if none saved → keep today’s single default local tab
- **🔷** **Open session in folder** — must work end-to-end (not only restore):
	- `Session.Controller.open_local(localhost, cwd)` already takes a directory
	- tree activate / “open” on a `LOCAL_PATH` row (or restore path) must spawn in that cwd
	- new tab from an existing local should keep using current cwd (already does via `open_new`)
- **🔷** **Root / elevated shells** — we **cannot** restore a root session:
	- after `sudo` / `su`, `/proc/<pid>/cwd` is often **EACCES**; do not invent a root reopen path
	- while still the normal user, keep registering cwd on label updates as today
	- once elevated, **freeze** the persisted path at the **last user location** registered before root
	- restore always spawns as the current user in that last user cwd (not as root, not home-by-default)
- **🚫** Do not invent a parallel “open tabs” file if `LOCAL_PATH` in `connections.json` is enough.
- **🚫** Restore as root / re-elevate on launch.
- **🚫** SSH / remote tab restore here — that is **Startup login / reconnect**.

#### Startup login / reconnect

- **🔷** Later: persist which **HOST** / LXC tabs were open; on launch run {@link Jobs.OpenSession} (login / sudo / lxc) per saved host.
- **🚫** Do not block local cwd restore on SSH restore design.
