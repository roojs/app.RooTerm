## Phase 1 — Precursor (catalogue + apply) `✔️`

### Catalogue (Guake → keyfiles)

- **🔷** Take Guake’s full **~169** as the stock set.
- **🔷** Convert once into **GKeyFile**s in a **gresource**; vendor in-tree (no runtime Guake / Python).
- **🔷** **Five** keyfiles — **one per background category**, named:
  - `theme-black.ini`
  - `theme-dark-grey.ini`
  - `theme-dark.ini`
  - `theme-off-white.ini`
  - `theme-white.ini`
- **🔷** Load all five into the list store in one go at startup / catalogue load.
- **🔷** Group = theme name; keys `foreground`, `background`, `palette` (16 colours); `#RRGGBB`.
- **🔷** When importing names: **strip Dark / Light** (and similar); tidy (e.g. `Solarized Dark` → `Solarized`).
- **🔷** Same tidy name **OK in different category files** (dark `Solarized` vs light `Solarized`) — that is why we split by file.
- **🔷** Attribute the colour data to Guake (fine).
- **ℹ️** Guake `palettes.py`: 16 palette + fg + bg each.
- **ℹ️** Ásbrú has per-colour YAML, not a scheme catalogue.

```ini
# e.g. resources/themes/theme-dark.ini  (GKeyFile comments are #, not ;)
[Solarized]
foreground=#708183
background=#001E26
palette=#002831;#d30102;...
```

### Background categories (for convert)

- **🔷** Classify from **background** luminance ± chroma (not name tokens).
- **🔷** Labels / files: **Black**, **Dark grey**, **Dark**, **Off-white**, **White**.
- **🔷** Cream + tiny mid-grey set → **Off-white**.
- **🔷** Math:
  - `L` = relative luminance of background
  - `chroma` ≈ max(RGB) − min(RGB)
  - black / dark grey / dark from low `L` + chroma cut
  - off-white / white from high `L`

### Theme objects + list models

- **🔷** Load all five keyfiles → {@link Theme} rows in {@link Themes} (top-level `RooTerm`, not `Terminal`).
- **🔷** `Themes` is `GLib.ListModel` over ArrayList (TreeNodes pattern); owned as `Config.themes`; `by_key` / `by_category`.
- **🔷** Prefs selectors (1.5) use `Gtk.FilterListModel` over `config.themes` (category `StringFilter`).

### Config + apply to terminals

- **🔷** Persist the selected theme on config — **name + category** (names are only unique inside a category file).
- **🔷** Replace hard-coded Solarized load in `Terminal/Base` with the **selected** theme (fg / bg / palette from the catalogue).
- **🔷** Theme changes apply to open terminals live (like opacity `notify`) — prefs selectors (1.5) drive this.
- **🔷** Missing / unknown selection → **first theme** in **Black** — keep it simple.
- **🔷** No migration from today’s hard-coded Solarized — user picks a theme when this ships.

## Phase 1.6 — Theme preview `✔️`

### Preview VTE

- **🔷** New **Theme preview** row under the selectors.
- **🔷** Live VTE, ~10 lines, `sensitive = false` (not editable).
- **🔷** 16 colours; a few coloured example words per line.
- **🔷** Loose line shape: often a command then short words — not two command columns.
- **🔷** Prompt line **first** (critical). Sketch approved (incl. dircolors bg lines + `echo` for leftover bright slots):

```
user@host:~/src$ _
ls   directory  symlink  executable  socket
     sticky+ow  other-w  setuid  setgid
     sticky  orphan  pipe
git  add  delete  commit  branch
gcc  error  warning  note
echo comment  match  ok  warn  info  header  meta  bright
dim  emphasis
```

- **ℹ️** Word colours follow common `ls` / `git` / `gcc` roles (directory, symlink, error, …).
- **🔷** `ls` continuation lines are GNU **dircolors** background samples (`sticky+ow` 30;42, `other-w`, `setuid`, `setgid`, `sticky`, `orphan`, `pipe`).
- **🔷** `echo` line = **leftover** palette slots not already shown above (the bright 8–15 set); not a full colour-name dump.
- **🔷** No Unicode ellipsis in the sample (dropped).
- **ℹ️** Guake’s own prefs preview is terrible — ours is the discovery path with ← / → (1.5).

### Transparency on preview

- **🔷** Preview follows `config.opacity`.
- **🔷** Prefs chrome is opaque — need a stand-in “desktop” behind the translucent VTE.
- **🔷** Use the **desktop background image** (wallpaper), crop the **middle** of it, and put that behind the preview.
- **ℹ️** On GNOME, wallpaper path is typically `org.gnome.desktop.background` `picture-uri` / `picture-uri-dark` (gsettings).
- **🔷** No usable wallpaper image → solid fallback (muted / off-blue).

- **🔷** `✔️` Theme preview row: live VTE, sketch above, `sensitive = false`.
- **🔷** `✔️` Wallpaper middle-crop (or off-blue) behind preview for opacity.
- **🔷** `✔️` Preview follows theme / opacity changes from selectors.

## Phase 2 — Customize `⏳`

### Behaviour

- **🔷** Start from the current theme; edit colours.
- **🔷** Save as base name + ` customized` (e.g. `Solarized customized`).
- **🔷** Still open: one customized slot per base name vs many “Save as…” names.
  - **💩** One slot (overwrite) — simpler.
  - **💩** Free Save-as — more UI, later.

### UI

- **💩** Colour buttons for fg, bg, and 16 palette slots.
- **💩** Editing switches selection to the `… customized` theme (or creates it).
- **💩** Reset drops custom data and re-selects stock.

### Storage

- **💩** Stock stays read-only in gresource; customized under user config (same keyfile shape if practical).

### Phase 2 tasks
